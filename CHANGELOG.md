## 0.1.0

- Несовместимые изменения
  - Требуется Node.js 24; установка зависимостей через `npm ci`
  - Имена `DEV_PROXY_URL`, `DEV_PUBLIC_PATH`, `DEV_APP_TOKEN` заменены на `PROXY_URL`, `PUBLIC_PATH`, `VITE_APP_TOKEN`
  - В корне находится минимальная SPA без Redux store и ISP API helper; для административных приложений используйте `isp-admin` или `isp-app`
- Добавлено
  - Независимые основы `minimal`, `isp-app` и `isp-admin` с собственными зависимостями и командами проверок и сборки
  - Генератор проектов с выбором основы, имени пакета, названия приложения, базового пути и API upstream
  - Собственная оболочка ISP App с сессиями, правами, общим RTK Query API и примером CRUD с фильтрами и пагинацией в URL
  - Основа на AdminBase с общим store, собственными маршрутами, правами страниц и действий, примером CRUD
  - Явный деморежим для разработки с учётными записями редактора, читателя и пользователя без доступа
  - Инструкции для агентов на английском, рецепты создания проектов и документация деплоя
  - Проверки всех вариантов в GitLab CI и Docker-матрица: шесть сборок для корня и подкаталогов, 12 сценариев запуска
- Изменено
  - Значение `PUBLIC_PATH` по умолчанию — `/`; путь меняется только по явному указанию и не выводится из имени папки, пакета или приложения
  - Название приложения задаётся через `package.json` → `config.appName`; генератор согласованно обновляет HTML и имена файлов деплоя
  - Docker выполняет один полный `npm ci` с кешем npm и отдельными слоями зависимостей и исходников
  - Сохранены исходные пути `/opt/msp/<project><PUBLIC_PATH>`, отдельный nginx-конфиг и shell-entrypoint; финальный образ работает без Node.js
- Исправлено
  - Сериализация строк Docker env в `config.js`, тип boolean для флагов входа и добавление `APP_NAME` только при явной передаче
  - Кеширование `config.js`, работа ресурсов, SPA fallback и переход на страницу входа AdminBase в подкаталогах
  - Проверка базового пути и API upstream до создания проекта с сохранением API rewrite и proxy headers
